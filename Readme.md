# SpkLathe: управление INTEK SPK153B43G по Modbus RTU (UWP, Windows 10 IoT Core)

## 1. Package.appxmanifest

Внутри `<Package>` добавьте (если нет, объявите `xmlns:m2="http://schemas.microsoft.com/appx/manifest/foundation/windows10"` как у шаблона):

```xml
<Capabilities>
  <DeviceCapability Name="serialcommunication">
    <Device Id="vidpid:0403 6001">
      <Function Type="name:serialPort" />
    </Device>
  </DeviceCapability>
</Capabilities>
```

Если у адаптера другой PID (FT232H = 6014), поправьте манифест и `SpkDrive.cs` (`OpenAsync`).

## 2. Параметры преобразователя (все взяты из руководства)

| Параметр | Значение | Зачем |
|---|---|---|
| P0.02 | 2 | команды пуска/стопа по связи |
| P0.03 | 9 | задание частоты по цифровой сети |
| P0.28 | 0 | плата связи Modbus |
| Pd.00 | 5005 (9600 бод) | скорость |
| Pd.01 | 0 | формат 8-N-2 (в коде так же) |
| Pd.02 | 1 | адрес |
| **Pd.05** | **31** | **стандартный Modbus.** По умолчанию 30 (нестандартный, ответ с 2-байтным счётчиком) |
| Pd.04 | 1.0 | сторожевой таймер, при пропадании связи ошибка 16 |
| P0.25 | 0 | время торможения отсчитывается от P0.10 до 0 Гц |

## 3. Карта регистров, использованная в коде

| Адрес | Назначение |
|---|---|
| 1000H | уставка частоты, % от P0.10 (10000 = 100.00 %) |
| 2000H | команда: 1 вперёд, 2 назад, 5 выбег, 6 стоп с торможением, 7 сброс ошибки |
| 3000H | состояние: 1 вперёд, 2 назад, 3 стоп |
| 7000H..7006H | d0.00..d0.06: частота, уставка, DC, Uвых, ток, мощность, момент |
| 8000H | код ошибки |
| 0011H / 0012H | P0.17 / P0.18, время ускорения/торможения 1 (ОЗУ, без износа EEPROM) |
| 0013H | P0.19, единица времени (0=1 с, 1=0.1 с, 2=0.01 с) |
| 000AH | P0.10, максимальная частота (0.01 Гц) |

Подключение: клеммы RS+ и RS- на плате управления (SPK153B43G это 15 кВт, встроенный RS485 есть), GND к общему.


Как проверить
Для кадра 01 03 00 00 00 01 правильный CRC равен 84 0A, то есть в кадре идут байты 84,
затем 0A (значение 0x0A84). Если подставить эти шесть байт в Crc16, должно получиться 0x0A84.
